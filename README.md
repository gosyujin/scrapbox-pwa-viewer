# scrapbox-pwa-viewer

Scrapboxプロジェクトのエクスポート JSON（設定画面の「Export」→ JSON）を、
単一の自己完結 HTML ファイル（+ Service Worker）に変換するビルドスクリプト。

- PC: 生成された HTML をダブルクリックで開くだけで、高速にページ一覧・検索・閲覧ができる。
- スマホ: **GitHub Pages で一度だけ公開し、Safari で一度開くと Service Worker がページ全体を
  キャッシュする。** 以降は機内モードでも通常のSafari（ホーム画面に追加すればアプリ風にも）で
  完全にオフライン動作する。
  （画像は外部URL参照のままなので、オフライン時は表示されない。テキスト・コード・リンク・
  バックリンクはすべてファイル内に埋め込み済みで問題なく見える）

> iOS Safari は `file://` でローカルHTMLを直接開く手段を持たず、Files アプリ経由の
> クイックルック表示は大きいファイルで固まりやすいため、GitHub Pages 経由での配布を採用している。

## 使い方

```bash
python3 build.py --input /path/to/export.json
```

- `--input` : Scrapbox からエクスポートした JSON ファイル
- `--output`: 生成する HTML のパス（省略時は `docs/index.html`。`sw.js` / `manifest.json` は
  同じディレクトリに自動生成される）
- `--title` : 表示タイトルを上書きしたい場合に指定（省略時はプロジェクトの表示名）

生成物は `docs/index.html`・`docs/sw.js`・`docs/manifest.json` の3つ。この3つを配布・
デプロイすればOK（他に依存ファイルなし）。

## GitHub Pages で公開してスマホをオフライン対応させる

1. このリポジトリを GitHub に push する
2. GitHub の Settings → Pages で Source を「Deploy from a branch」、
   Branch を `main` / フォルダを `/docs` に設定
3. 発行された `https://<user>.github.io/<repo>/` を **一度だけネット接続した状態で** iPhone の
   Safari で開く（Service Worker がページ全体を裏でキャッシュする）
4. 以降は機内モードでも同じURLを開けば完全にオフラインで動作する。共有シートから
   「ホーム画面に追加」すればアプリのように起動できる

再エクスポートしてページ内容を更新したときは、同じ手順で `docs/` を再生成して push すれば良い。
`sw.js` のキャッシュ名にはエクスポート日時が埋め込まれるため、内容が変わっていれば
ファイルのバイト列も変わり、ブラウザの更新チェックで新旧を区別できる。次にオンラインで
アプリを開いた（またはアプリをフォアグラウンドに戻した）タイミングで自動的に新しい内容を
取得・適用（ページの自動リロード）する。画面下部の更新ボタン（⟳）を押せば即座にチェックできる。
一覧の先頭に表示される「データ取得: …」が、今見ている内容がいつ時点のエクスポートかを示す。

## 動作確認（ローカルでプレビューする場合）

```bash
cd docs && python3 -m http.server 8000
```

その後 `http://localhost:8000/` を開く。

## 機能

- 全ページの一覧・検索（タイトル優先、本文もヒット、ハイライト表示）
- ページ間リンク（`[リンク]` / `#タグ` / `[[強調リンク]]`）のクリック遷移
- リンクの色分け：内部リンク（存在するページ）＝青、内部リンク（存在しないページ）＝赤、
  外部リンク＝緑
- 被リンク（backlinks）一覧をページ末尾に表示
- コードブロック（`code:filename`）、テーブル（`table:name`）、引用（`>`）、
  太字/斜体/打ち消し線などの装飾、インデントによるアウトライン（箇条書き）に対応
- 拡張装飾記法（`[X テキスト]`、Xは`*-/_`以外の記号1文字）にも対応。`settings` ページの
  カスタムCSS（`.deco-\X`）に定義がある `<`（キーキャップ）・`>`（メニューパス）・
  `"`（引用符）・`!`（タイムスタンプ）・`~`（ミニ画像）・`#`（省略）はそれ用のスタイルを
  再現。CSSが定義されていない記号（`$`の数式記法など）は無装飾のプレーンテキストとして
  表示される（実際のScrapboxと同じ挙動）
- 画像（Gyazoなど）はリンク先URLを保持したまま埋め込み表示（オンライン時のみ表示される）
- ライト/ダークモード自動切替
- モバイル幅（760px以下）ではトップページ＝ページ一覧を直接表示し、画面上部に
  常時表示のヘッダー（データ取得日時／ホームボタン・更新ボタン・検索ボックス・
  ランダムボタン🎲）を配置。ページ閲覧中もヘッダーは残り、下側がページ内容に切り替わる。
  ランダムボタンは全ページからその場でランダムに1件選んで遷移する（厳密な一様乱数である
  必要はなく、適当にいろいろなページを渡り歩ければ十分という想定）
- PC幅ではホームボタンの代わりにヘッダー左のプロジェクト名（`.brand`）自体がトップページへの
  リンクになる（モバイル幅では `.brand` が非表示になるため、その代替としてホームボタンが
  現れる——両者は排他的で常にどちらか一方だけが表示される）
- ヘッダーに常時「データ取得: YYYY-MM-DD HH:MM ／ ビルド: <commit>」を表示（`<head>` にも
  `<meta name="scrapbox-exported-at">` / `<meta name="build-commit">` として埋め込み）。
  今見ている内容がいつ時点のエクスポート・どのコミットのビルドかが一目でわかる
  （表示されるコミットhashは、その内容を生成した直前のコミット。生成物自身のコミットは
  ビルド後に作るため、自分自身のhashを埋め込むことはできない）
- Service Worker によるオフラインキャッシュ（初回アクセス後は機内モードでも動作）。
  `sw.js` のキャッシュ名はエクスポート日時とビルドコミットの両方から作られるため、
  データを再エクスポートしなくてもコードだけの変更で確実にキャッシュが更新される。
  オンラインで開く／フォアグラウンドに戻すと自動更新を試みるが、ブラウザによっては
  即座に効かないことがあるため、更新ボタンは Service Worker 登録解除＋キャッシュ全削除＋
  強制再取得という確実な手段で更新する
- 各ページに「メモ」欄（textarea）があり、入力内容はこの端末の `localStorage` に
  ページ単位で自動保存される（Scrapboxのエクスポートデータには含まれない、閲覧用端末だけの
  一時メモ）。メモを書いたページは一覧でペンアイコンが付く。一覧上部の「メモを全部コピー」で
  書き溜めた全ページ分を
  ```
  [ページタイトル]
  メモ本文

  [別のページタイトル]
  メモ本文
  ```
  の形式で1つのテキストにまとめてクリップボードにコピーする（失敗時は選択・手動コピー用の
  ダイアログを表示）。想定用途は、機内などオフラインでビューアを見ながら「n行目を直したい」
  等のメモを書きためておき、オンラインに戻ったらまとめてコピーして元のScrapboxプロジェクトに
  手作業で貼り付け・反映すること。「クリア」で保存済みメモを全削除できる
- 上記とは別に、どのページにも紐付かない「作業用メモ」を1つ持てる（モバイル幅では一覧上部の
  メモバー直下、PC幅ではホーム画面の `#main` に大きく表示——レイアウトに応じてどちらか
  一方のみ表示される、実体は同じ`localStorage`の値）。ページ単位のメモと全く同じ形式
  （`[作業用ページ]` を見出しとして直後に本文、間に空行なし）で「メモを全部コピー」に含まれる
- メモ欄では `[` を入力すると Scrapbox と同様に自動で `[]` になりカーソルが間に入る
  （選択中の文字列があればそれを `[]` で囲む）。`[...]` の中にカーソルがある間、入力内容に
  部分一致する既存ページタイトルの候補が入力欄の下に一覧表示され、クリックすると
  `[...]` の中身をそのタイトルに置き換える。カーソル位置に追従するポップアップではなく
  常に入力欄の下に固定表示する簡易版（候補の矢印キー選択もなし）だが、その分
  実装がシンプルでモバイルのソフトキーボード表示中でも崩れにくい

## ディレクトリ構成

```
build.py            変換スクリプト本体（Scrapbox記法パーサ含む）
templates/
  shell.html         出力HTMLの骨格
  style.css           スタイル
  app.js              クライアント側ロジック（検索・ルーティング・描画）
  sw.js               Service Worker（そのままdocsにコピーされる）
docs/                 生成物の出力先。GitHub Pagesの公開元
```

## 制限事項・既知の非対応記法

- 画像・アイコンはダウンロードせず外部URL参照のまま（オフライン時は非表示）
- KaTeX数式 (`[$ ...]`) は未対応（プレーンテキストとして表示）
- ページ内リンクの解決はタイトルの完全一致（大文字小文字無視）のみ。別プロジェクトへの
  リンク（`/project/page`）は外部リンク的に扱われる
- GitHub Pages は公開リポジトリ前提（URLを知っていれば誰でもアクセス可能）
